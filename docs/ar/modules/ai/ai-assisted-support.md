# دعم أفضل باستخدام وكيل ذكاء اصطناعي

معظم أسئلة الدعم إجابتها موجودة بالفعل في مكانٍ ما من هذا الموقع — المشكلة في العثور على الفقرة. تصلك مشكلة تقول «الفاتورة لم تُنشئ قيد اليومية»، والإجابة الصحيحة تتطلب معرفة الشاشة التي يقع فيها الإعداد، واسم الحقل بالعربية، والجدول الذي تُخزَّن فيه القيمة، وهل هناك تنبيه في مكانٍ ما يقول إن الأمر لا رجعة فيه. هذه أربع أو خمس صفحات، والشخص الذي يقرؤها لديه عميل ينتظر.

**وكيل الذكاء الاصطناعي البرمجي (AI coding agent)** يحل هذا بطريقة مختلفة. بدلًا من البحث في موقع، تعطي الوكيل التوثيق كاملًا ونموذج البيانات كملفات على جهازك، ثم تسأل سؤالك بالعربية أو الإنجليزية ببساطة. فيقرأ الصفحات، ويقتبس لك مسار القائمة، ويعطيك الجدول والعمود، ويناولك رابطًا ترسله للعميل. ما كان بحثًا يستغرق عشر دقائق يصير سؤالًا وإجابة.

بل يتجاوز ذلك بكثير. فبمجرد أن تربط الوكيل بنظام نما حقيقي عبر [خادم MCP](./ai-mcp-server.md)، يتوقف عن الإجابة من الدليل وحده ويبدأ الإجابة من نظام العميل نفسه — يقرأ السجلات، ويقرأ كيف ضُبط التوجيه والإعدادات، وينفّذ استعلامًا على البيانات، ويشرح لماذا تصرّف المستند بالشكل الذي تصرّف به.

تشرح هذه الصفحة الإعداد كاملًا، من جهاز لا يحوي شيئًا إلى وكيل قادر على تشخيص مشكلة حقيقية.

::: info لمن هذه الصفحة
لموظفي الدعم الفني في نما، ولمديري الأنظمة لدى العملاء الذين يريدون القدرة نفسها داخل شركاتهم. لست بحاجة إلى أن تكون مبرمجًا — الخطوات التالية نسخ ولصق.
:::

## الخطوة الأولى: تثبيت Git

Git هو الأداة التي تنزّل قاعدة المعرفة وتبقيها محدَّثة. افتح سطر الأوامر واكتب `git --version`؛ فإن أجابك برقم إصدار فهو مثبَّت لديك وتستطيع الانتقال للخطوة التالية.

وإن لم يكن مثبتًا:

- **ويندوز** — ثبّته من [git-scm.com/download/win](https://git-scm.com/download/win)، أو نفّذ `winget install --id Git.Git -e` في PowerShell.
- **ماك** — نفّذ `xcode-select --install`، أو `brew install git` إن كنت تستخدم Homebrew.
- **لينكس** — `sudo apt install git` على Debian/Ubuntu، و`sudo dnf install git` على Fedora أو RHEL.

أغلق سطر الأوامر ثم افتحه من جديد بعد التثبيت حتى يتعرّف على الأمر الجديد.

## الخطوة الثانية: استنساخ قاعدة معرفة الدعم

قاعدة المعرفة مستودع واحد يجمع شيئين: موقع التوثيق هذا، و[موقع نموذج البيانات](https://dm.namasoft.com) الذي يصف كل جدول وعمود وقائمة قيم في النظام. ويحمل معهما مجموعة تعليمات تُعرّف الوكيل بطريقة تنظيم نما — أين تقع الوحدات، وأن الصفحات العربية مرآة للإنجليزية، وأن ملف الأصناف اسمه `InvItem` لا `Item`، وكيف يوثّق مصدر ما وجده.

اختر مجلدًا تتذكّره ونفّذ:

```bash
git clone --recurse-submodules https://github.com/ahmedqasid/namaerp-support-kb.git
cd namaerp-support-kb
```

::: warning لا تنسَ `--recurse-submodules`
التوثيق ونموذج البيانات مرتبطان كوحدات فرعية (submodules). إن استنسخت بدون هذا الخيار حصلت على مجلدين فارغين ووكيل لا يجد شيئًا ليقرأه. وإن حدث ذلك، نفّذ `git submodule update --init --recursive` داخل المجلد لتعبئتهما.
:::

المحتوى يتحرّك مع كل نشر للموقعين، فاسحب التحديثات في بداية يوم العمل كما تُحدِّث صفحة في المتصفح:

```bash
git pull
git submodule update --init --recursive
```

## الخطوة الثالثة: تشغيل وكيل برمجي داخل المجلد

الوكيل البرمجي برنامج يعمل من سطر الأوامر، يقرأ الملفات وينفّذ الأوامر ويجيب عن الأسئلة المتعلقة بالمجلد الذي شغّلته بداخله. شغّله **داخل `namaerp-support-kb`** — فهذا ما يمنحه التوثيق — ثم اسأل سؤالك كما تسأل زميلًا.

نوصي بـ **[Claude Code](https://docs.claude.com/en/docs/claude-code)**. ثبّته بسطر واحد:

```bash
# ويندوز (PowerShell)
irm https://claude.ai/install.ps1 | iex

# ماك / لينكس
curl -fsSL https://claude.ai/install.sh | bash
```

ثم انتقل إلى مجلد قاعدة المعرفة، واكتب `claude`، وابدأ السؤال.

::: tip الوكلاء الآخرون يعملون أيضًا — لكن ليس بالكفاءة نفسها
جرّبنا **Codex**، وكيل OpenAI البرمجي، على قاعدة المعرفة نفسها فوجدناه يعمل: يجد الصفحات ويجيب إجابات صحيحة. لكن في الاستخدام المتوازي على أسئلة نما الحقيقية كان Claude Code أقوى بوضوح — يلتزم بتعليمات المستودع بدقة أكبر، ويقرأ صفحات أكثر قبل أن يجيب بدل أن يكتفي بأول نتيجة، ويحافظ على تماسك التشخيص الطويل. فإن كان الاختيار بيدك، فاختر Claude Code.
:::

ومن هنا يمكنك أن تسأل أسئلة مثل:

- «العميل يقول إن قيد اليومية لم يتكوّن للفاتورة — من أين أبدأ؟»
- «أي جدول يخزّن قيم بنود الراتب، وما اسم عمود المبلغ؟»
- «ماذا يفعل مسار الكيان `EAGenJournalEntry`، وما المدخلات التي يحتاجها؟»
- «أعطني مسار القائمة لإعداد الفترات المحاسبية، ورابط التوثيق الذي أرسله للعميل.»

## الخطوة الرابعة: ربط الوكيل بنظام حقيقي

كل ما سبق مكتبة ممتازة. أما الخطوة التي تغيّر طبيعة العمل فهي ربط الوكيل بنظام نما فعلي عبر **MCP** — البروتوكول القياسي الذي تستخدمه برامج الذكاء الاصطناعي للوصول إلى الأنظمة الخارجية. ونما يحتوي على خادم MCP مدمج، فلا شيء يُثبَّت على الخادم سوى وحدة الذكاء الاصطناعي نفسها.

بعد الربط يستطيع الوكيل أن يقرأ السجلات، ويطّلع على كيفية ضبط نوع مستند، ويسرد الإعدادات التي تقف خلف سلوكٍ ما، ويشغّل تقريرًا، وأن يُنشئ السجلات ويعدّلها حين تسمح له بذلك. عندها يتحول السؤال من «ماذا يقول الدليل عن حدود الائتمان؟» إلى «لماذا تعطّل *هذا* الطلب تحديدًا؟» — وهو سؤال يجيب عنه الوكيل بقراءة العميل والتوجيه وإدخال الإعدادات الذي يحكمه.

أما الربط نفسه فبضعة أسطر في ملف إعدادات الوكيل:

```json
{
  "mcpServers": {
    "nama-erp": {
      "type": "http",
      "url": "https://<customer-server>/basic-services/mcp",
      "headers": { "X-API-Key": "<client-secret>" }
    }
  }
}
```

أما عنوان الخادم، وترويسات المصادقة، وسجل **بيانات اعتماد الواجهة البرمجية (API Credentials)** الذي يأتي منه المفتاح، وكيف يُنفَّذ كل نداء بهوية مستخدم حقيقي تسري عليه صلاحيات النظام كاملة — فكلها مشروحة في صفحة [خادم MCP لنظام نما ERP](./ai-mcp-server.md). اقرأها قبل أن تربط، وخصوصًا الجزء المتعلق بتخصيص مستخدم بصلاحيات محسوبة بدل توجيه الوكيل إلى حساب مدير النظام طلبًا للراحة.

## الخطوة الخامسة: امنح الوكيل الأدوات الصحيحة

اتصال MCP وحده لا يكشف شيئًا. فالوكيل لا يستطيع استدعاء إلا الأدوات التي عرّفها مدير النظام في شاشة **AI Tool Definition**، ولذلك فهذه الخطوة هي التي تقرّر مدى قدرة الوكيل — ومدى خطورته. وهناك ثلاث مجموعات من [أدوات النظام](./ai-tool-definitions.md) الجاهزة تستحق إعدادًا مدروسًا.

### أدوات السجلات — للجميع، ومحدودة بالصلاحيات

أدوات التصدير والاستيراد الست، التي تُضاف بنقرة واحدة عبر زر **Add Export Tools**، تتيح للوكيل أن يحوّل مصطلحًا عربيًا أو إنجليزيًا إلى نوع كيان، ويبحث في السجلات، ويقرأ سجلًا بصيغة JSON، ويسرد القيم المسموحة لحقل، ويعرف مخطط استيراد كيان، ويستورد سجلات جديدة.

والخاصية المهمة هنا أن **كل واحدة منها تمر عبر البوابات نفسها التي تمر منها الشاشات**. فإن كان المستخدم المرتبط لا يرى مستندات شركة معينة، فالوكيل لا يراها كذلك. وإن كان لا يملك إنشاء فواتير مشتريات، رُفض نداء الاستيراد. هذه الأدوات محدودة تمامًا بالصلاحيات التي تأتمن ذلك المستخدم عليها أصلًا، وهذا ما يجعل إتاحتها لموظفي الدعم عمومًا أمرًا معقولًا.

### أداة الاستعلام SQL للقراءة فقط — لمديري النظام وحدهم، وغير محدودة

أضف `AITReadOnlySQLQuery` سطرًا في جدول **System Tools Configuration** فيحصل الوكيل على أداة واحدة، `<prefix>runReadOnlySqlQuery`، تنفّذ عبارة `SELECT` واحدة بلغة T-SQL على قاعدة البيانات وتعيد الصفوف بصيغة JSON.

هذه هي الأداة التي تغيّر طبيعة تتبّع المشكلات. فمع نموذج البيانات الموجود في قاعدة المعرفة، يستطيع وكيل يملك الاستعلام المباشر أن يجد المستندات الاثني عشر التي لم تُعَد تكلفتها، أو يقارن إعدادًا عبر سبع شركات، أو يتتبّع فرقًا في رصيد وصولًا إلى القيود الثلاثة التي سبّبته — وهي تحقيقات كانت ستكلّف يومًا من عمل مبرمج. إنها الفرق بين وكيل يصف كيف *يُفترض* أن يعمل النظام، ووكيل يخبرك بما حدث فعلًا في قاعدة البيانات هذه.

وهي في الوقت نفسه الأداة التي تتطلب أكبر قدر من الحذر، لسبب واحد محدد:

::: danger أداة SQL غير محدودة بصلاحيات المستخدم
أدوات السجلات محدودة بما يستطيع المستخدم المرتبط قراءته. **أما أداة SQL فلا.** فهي تقرأ قاعدة البيانات مباشرة، وترى كل شركة وكل فرع وكل راتب وكل سعر — بصرف النظر عمّا يُسمح لمستخدمها بفتحه على الشاشة. اقصرها على مديري النظام عبر جدول **Security (Access Control)** في تعريف الأداة، وعلى مديري النظام وحدهم.
:::

أما ما لا تستطيعه فهو التغيير. لا يُقبل سوى `SELECT` واحدة: أما `INSERT` و`UPDATE` و`DELETE` و`EXEC` وعبارات تعديل البنية و`SELECT ... INTO` وتعدد العبارات في نداء واحد والدوال التي قد تصل إلى خادم آخر فكلها تُرفض قبل تنفيذ العبارة. وما يُنفَّذ فعلًا يجري داخل معاملة يجري التراجع عنها دائمًا، فحتى العبارة التي تفلت من الفحص لا تترك أثرًا. والنتائج محدودة أيضًا — ٢٠٠ صف في النداء الواحد افتراضيًا، ويمكنك رفعها إلى ٥٠٠٠ كحد أقصى بوضع العدد في عمود المُدخل الأول للسطر، مع مهلة تنفيذ قدرها دقيقة واحدة.

### أدوات التوجيهات والإعدادات — السلاح اليومي لمدير النظام

أضف `AITTermAndConfigTools` فيحصل الوكيل على أربع أدوات تغطي شاشات الإعدادات: واحدة تسرد ما يمكن ضبطه، وواحدة تصف إعدادات توجيه نوع مستند أو إدخال إعدادات — مجمّعة بالطريقة نفسها التي تجمّعها بها الشاشة، ومع التسمية العربية والإنجليزية لكل إعداد — وواحدة تقرأ القيم الحالية، وواحدة تحدّثها.

بالنسبة لمدير النظام هذا هو الفرق بين أن تعرف أن الإعداد موجود وأن تجده. فالإعدادات العامة تضم آلاف الإعدادات موزعة على سبع عشرة صفحة، والتوجيه الواحد يضم المئات. وسؤال مثل «كيف ضُبط توجيه فاتورة المبيعات فيما يخص مركز التكلفة، وأي إعداد يتحكم في ذلك؟» صار يعطيك الإعداد وتسميتيه وصفحته وقيمته الحالية في إجابة واحدة بدل جولة على الشاشات. وأداة التحديث تدمج التعديل على الإعدادات المحفوظة بدل أن تستبدلها، وتُبلغك بالقيمة القديمة والجديدة لكل ما غيّرته، وتستطيع إنشاء توجيه غير موجود بعد.

::: warning كل ما يفعله الذكاء الاصطناعي يجب أن يُراجَع
هذا ليس تحفّظًا على نما — بل هو صحيح مع كل أداة ذكاء اصطناعي. فالنموذج قد يسيء فهم السؤال، أو يختار حقلًا معقولًا لكنه خاطئ، أو يكتب استعلامًا يجيب عن سؤال مختلف قليلًا عمّا سألت. اقرأ ما فعله قبل أن تبني عليه: راجع الاستعلام الذي نفّذه، والإعداد الذي غيّره، والسجل الذي أنشأه. واستورد كمسودة أولًا حين يكون التغيير مهمًا. الوكيل مساعد سريع جدًا، لا مساعد بلا إشراف، ومراجعته تستغرق جزءًا يسيرًا من زمن العمل الذي وفّره.
:::

## أخبرنا حين يفشل

أثمن ما يستطيع مدير نظام أو مهندس دعم أن يقدّمه للدعم المعزّز بالذكاء الاصطناعي في نما هو أن يخبرنا حين لا ينجح.

كل واحدة من هذه الحالات تهمّنا:

- لم يجد الوكيل شيئًا موجودًا بوضوح في النظام.
- تعثّر في سؤال يعدّه موظف الدعم سؤالًا بسيطًا.
- دار في حلقة مفرغة، أو استسلم أمام مهمة كان ينبغي أن تكون مباشرة.
- التوثيق يقول شيئًا والنظام يفعل شيئًا آخر — التعارض عيبٌ في التوثيق، ونريد إصلاحه.
- أعادت أداةٌ نتيجة مربكة، أو رفضت ما كان ينبغي أن تسمح به.

كل بلاغ يدلّنا بالضبط على الصفحة التي نعيد كتابتها، أو وصف الأداة الذي نحسّنه، أو القدرة الناقصة التي نضيفها. راسلنا على **[ai@namasoft.com](mailto:ai@namasoft.com)** — جملة تصف ما سألت عنه وما حدث تكفي — أو أوصل الأمر عبر قناتك المعتادة مع نما. وكلما زادت هذه البلاغات كانت الإجابة التالية أفضل للجميع.
